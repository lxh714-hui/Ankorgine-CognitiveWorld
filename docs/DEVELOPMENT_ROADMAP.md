# CognitiveWorld Development Roadmap

## B2 scoped L1 identity and proof milestone (2026-10-24)

The local B2 implementation establishes the default immutable owner/Timeline/
Observation consumption instance, original L1 acceptance tick, and a separate
instance-bound v2 proof for B1's private locked-door failure. Acceptance and
proof completion share Runtime fencing; post-L1 failures freeze writes/capture.
Published-checkpoint verification, cold-resume ambiguity denial and exact
ancestor-checkpoint record membership preserve branch isolation. This is a
narrow evidence milestone, not general learning, independent re-consumption,
uncheckpointed recovery, B3 expectation persistence or B4 cognitive revision.
Legacy v1 proofs and outer save identities are unchanged. See the
[B2 contract](DATA_CONTRACTS.md#b2-durable-l1-identity-and-instance-bound-proof)
and [local verification record](REPOSITORY_STATUS.md) for scope and evidence.

## Hybrid associative retrieval — narrow semantic and Event-anchored slices implemented; broader design approved

The existing 12.2 lexical path remains the baseline. The Event-anchored locator is connected to `AgentTurn`, and an optional semantic candidate strategy can be injected through its existing `CognitionContext` retrieval path. No Event IDs are extracted from natural language. The broader hybrid direction should continue only through separately reviewable stages; each stage requires its own task scope and tests:

1. **Recall baseline — completed for the current lexical corpus:** the fixed evaluation suite records Recall@K/MRR for its labeled queries and tracks no-answer, owner scope, candidate scans, canonical reads, and result count. It remains a small artificial corpus, not a general quality claim.
2. **Minimal derived Event index — narrow slice implemented:** `MemoryEventIndex` rebuilds Event→Memory locators from authorized Character-linked canonical Memory and fully verified Runtime EventHistory. AgentTurn consumes only current L1 Observation anchors whose Event, evidence, and Timeline match. Deterministic rebuild, canonical Store rechecks, owner/Character isolation, lexical fallback, stale-history/index rejection, and no-write behavior have targeted coverage. Alias discovery and general entity/semantic graph links are not implemented.
2a. **Minimal semantic candidate channel — narrow slice implemented:** A replaceable embedding strategy ranks a query-local authorized Memory subset; lexical order is preserved, and similarity only fills unused slots before the separately verified Event channel. Timeout/invalid-vector failures degrade to lexical retrieval. The fixed corpus uses unchanged gold labels, permissions and top-five budget; a deterministic provider demonstrates one configured synonym recovery, not general semantic quality. An optional local Ollama `/api/embed` transport exists, but no model is enabled by default and real-model quality is not accepted. No persistent vector database, global read budget or general AgentTurn UI scheduling is included.
3. **Bounded associative propagation:** add query-local activation with explicit hop/fan-out/candidate/compute limits and separate causal versus semantic traversal. Test loop suppression, temporal/directional causal constraints, and that semantic paths only add candidates.
4. **Candidate fusion:** merge and deduplicate direct lexical/entity, semantic, temporal/event, and association results while retaining source, time, path, authorization and evidence state; rerank without treating similarity/activation/importance as truth. Test paraphrases, temporal changes, conflicting experiences and evidence preservation.
5. **Bounded metacognitive follow-up:** allow a limited additional query plan only for explicit evidence gaps/conflicts or response needs. Test maximum rounds/candidates/budget, no-answer calibration, uncertainty on exhaustion, and no cognition writes.
6. **Independent evaluation gate:** expand index structure or scheduling only if evaluation demonstrates a material gain without unacceptable false-memory, evidence-completeness, permission, latency, or compute regressions.

The test set should include lexical misses recovered through an authorized association path, aliases/paraphrases, time-varying records, contradictory experiences, bounded multi-hop discovery, permission isolation, and no-answer queries. These are planned acceptance cases, not current test coverage. Exact decay equations and channel weights remain experimental until measured.

## Phase 12–16 之后的跨阶段增量

这些增量是既有能力的后续接续，不是重复 Phase：

- **玩家输入到行动/澄清的纵向路径 — IMPLEMENTED NARROW / PARTIAL**：`submit_input` 通过有界解释 Provider 区分行动候选、无法解析、缺少必要信息及推理不可用。澄清问题与无结果旁白分别使用隔离展示类型；只有行动候选进入既有 Safety、授权目标、Resolution、EventProcessor 路径。目标只从玩家当前授权 Observation 校验。该切片不代表一般语言理解、任意语义正确性或 CWUI 生产接线；模型输出仍可能误导，展示隔离确保它本身没有世界写权限。
- **玩家言语到接收者 Agency — IMPLEMENTED / PARTIAL**：`PlayerDialogueService` 将 host-bound、同地点的玩家言语作为 `dialogue_input` 经 EventProcessor 记录，并只向指定注册接收者签发 Observation。接收者 L1 消费后，可由显式 Provider 提出回应候选，现有 AgentDecision 评估并选择；选中的 `dialogue_reply` 经受控 Event、定向 Observation 与 Presentation 投递。接受代理行动时 NPC 为 Attempt actor，原发送者为 initiator；拒绝、澄清和未决定不自动提交该行动。已运行一个本地 Ollama 合成闭环，但通用目标 grounding、自由语言改写、私有信息披露判定及一般语义质量仍未验收。独立的 opt-in Persuasion 现可受治理地修订接收者既有 Belief；Goal 说服尚未实现。
- **InteractionReference — IMPLEMENTED / PARTIAL**：明确 `object:{id}` / `agent:{id}` 地址并保留裸 object ID 兼容。namespace 不是授权或目标存在证明；AgentDecision 的模型候选目标现在必须精确引用该 Agent 当前观察到的 subject 或 affordance，避免候选模型凭空生成引用。该成员资格检查不做语义消歧、不证明目标存在/可达/有权限；Agent 目标的因果裁定、任意对象 grounding 尚未实现。
- **受控证据查询 — IMPLEMENTED / TESTED / PARTIAL**：`AuthorizedStateQuery` 只读当前 owner 已授权、来源可核验、在事件时点成立且匹配 Attempt 目标的 Observation facts；查询有预算和严格结构契约。它不读取完整 WorldState，不授权事实或结果。
- **最小交互单元动态状态聚合 — IMPLEMENTED / TESTED / PARTIAL**：`InteractionStateAggregator` 按一次 Attempt、目标引用和 clock-issued tick 临时构建物理视图；通过 WorldState 定向读取 actor、位置、能力、自有工具和一个 typed 环境目标，并将 attempt fingerprint、read-source refs 与未知字段绑定到 `CausalWorldContext`。`MethodBasedResolutionEngine` 已使用该物理视图，所以现有门/通道裁定经过聚合边界。可选认知视图只通过同 owner 的 `AuthorizedStateQuery` 返回该角色已有的可信 Observation facts，最多查询现有预算内的目标并保留 Event/Observation 来源。没有缓存、Store 或写权限。当前物理领域仍只有门与已知通道；认知视图不读取 Belief/Goal/Memory/Emotion，也不属于 Cognitive Causality。

## Hybrid physical engine and independent LOD — architecture approved, implementation planned

The current engine only adjudicates the installed door and known-passage transitions through Attempt-bound physical proposals and the normal EventProcessor path. It has no general position/orientation contract, 3D coordinate transform service, material/structure response model, collision engine, continuous integrator, or runtime LOD scheduler. The architecture design distinguishes canonical world coordinates from observer-local polar/spherical projections and keeps cognitive, perceptual, and physical-computation LOD independent. Distance is only one scheduling signal; collision proximity, velocity, energy, constraints, hazard, uncertainty, consequence severity, and model validity can require escalation. If escalation is necessary but unavailable, Resolution remains unresolved.

Implementation order (each stage requires its own task approval and does not imply production readiness):

1. **Coordinate and unit foundation:** define immutable typed 3D positions/orientations and versioned local-frame transforms; test round trips, origin changes, and multiple observers against an unchanged canonical WorldState.
2. **Deterministic spatial queries:** add bounded spatial indexing/query contracts and conservative collision candidate detection without state writes; test boundaries and stable results.
3. **One physical vertical slice:** choose a world-configured receiver response and collision rule; bind assessment to Attempt/tick/state-slot reads/model version/uncertainty, then resolve through EventFactory and EventProcessor. Unsupported cases remain unresolved.
4. **Independent LOD budgets:** define separate cognitive/perceptual/physical requests and outputs, with an aggregate budget coordinator, deterministic escalation triggers, disagreement handling, and fail-closed exhaustion tests.
5. **Bounded motion approximation:** only after the preceding slice demonstrates need; specify step-size error bounds and replay determinism before expanding domains or multiple-body propagation.

No tests or implementation are claimed for these planned stages. Do not build a general simulator or merge the three LOD axes into one distance threshold.

The synchronous service remains available, and the later `anchor_desktop` product gateway now uses this coordinator with allowlisted task/status DTOs. There is still no durable outbox, restart recovery of tasks or cross-generation delivery protocol; ordinary visible client acceptance remains separate.

Every future Core/application/UI slice must check framework independence, long-running work off the UI main thread, request and Runtime-generation binding for asynchronous results, cancellation/timeout/replay/shutdown behavior, thin authorized DTO projections, distinct fact/Observation/clarification/Narrative Fallback/progress/error channels, and the rule that delivery failure cannot alter committed facts. Record which items are implemented and tested, designed but not implemented, or still unverified; do not promote a design constraint to an implementation claim.

Suggest a bounded central architecture review when a change crosses multiple modules or reveals drift between application, Presentation, Runtime, and client contracts. For a local change with clear existing contracts, perform the boundary check within that slice and keep scope local. A new UI or asynchronous task system should be planned as a separate deliverable with lifecycle, recovery, authorization, and projection acceptance criteria; this gate does not imply that such infrastructure exists today.
